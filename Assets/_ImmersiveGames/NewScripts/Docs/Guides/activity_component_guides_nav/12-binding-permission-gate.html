Binding prepara, Gate libera

O binding conecta as peças. O gate decide se a capacidade está Allowed, Blocked ou Unbound conforme o lifecycle da Activity.

Entry ↓ Binding prepara PlayerInput, Movement, Camera, CommandHub Gate = Blocked ↓ ActivityRunning Gate = Allowed ↓ Completion / RouteExit Gate = Blocked ou Unbound

Exemplo: movimento do player

PlayerInput → PlayerActorCommandInputHub → ActorCommandEnvelope Move → PlayerMovementController → PlayerMovementPermissionReceiver → ActivityGameplayControl Allowed/Blocked
O hub não decide permission. Ele só emite comando local. Quem libera/bloqueia é o gate/permission runtime.

Erros comuns

  • Movimento funcionar antes de ActivityRunning: gate está errado.
  • Activity no-content perder movimento do player persistente: binding não foi revalidado na entry.
  • Permission resolver por texto de actor/slot: identity está errada.
  • Hub executando gameplay direto: capability/endpoint foi pulado.
